# 原创短篇故事平台：第一版功能拆解

状态：**等待确认，尚未进入开发**

## 1. 产品目标

第一版只验证一条核心链路：

作者投稿 → 管理员审核并发布 → 游客阅读免费部分 → 用户付费解锁全文 → 用户完成阅读。

本阶段不建设 AI 写作、作者后台、IP 交易、短剧改编、排行榜、社交关系、积分金币、复杂推荐算法或版权撮合系统。

产品结构参考千图网（58pic）的“用户提交 → 平台审核 → 内容上架 → 免费预览 → 付费获得完整权益”模式，但内容对象改为原创短篇故事。参考的是业务结构，不复制其视觉设计、文案、代码或素材。

## 2. 必须先澄清的产品前提

以下内容尚不能当作已确定事实，开发前需要逐项决定：

1. **支付渠道与经营主体**：微信/支付宝等真实收款需要合规经营主体、支付渠道和服务端回调。没有这些条件时，只能先完成支付接口和测试环境，不能上线真实交易。
2. **投稿身份验证**：投稿必须注册并登录。注册方式仍需决定使用邮箱验证码、手机号验证码或两者均支持；投稿接口仍需频率限制和重复稿检测。
3. **稿费与分成结算**：首版可以记录稿件采用价格和分成比例，但自动结算涉及身份、税务、退款和对账，建议第一阶段由管理员线下结算，系统只留审计记录。
4. **免费比例**：30%～50% 不能写死在页面。应由每篇文章单独设置付费墙位置，并按真实数据调整。
5. **“禁止复制”不是防盗能力**：前端禁用复制只能增加操作成本，不能阻止截图、抓包或爬取。首版应采用权限校验、限流和用户水印，但不承诺绝对防盗。

## 3. 用户与权限

### 3.1 游客

- 浏览已发布故事列表。
- 搜索或按简单类型筛选故事。
- 阅读故事的免费部分。
- 打开投稿说明页；注册并登录后才能提交完整稿件。
- 登录或注册后购买故事。

游客不能：

- 读取付费正文。
- 查看、修改或撤回投稿。
- 访问管理端。

### 3.2 已登录读者

- 拥有游客全部能力。
- 创建支付订单并解锁故事。
- 查看自己的已购故事。
- 在不同设备上恢复购买记录。

### 3.3 管理员

- 通过独立入口登录管理端。
- 查看投稿列表和投稿详情。
- 审核、驳回、要求修改或采用投稿。
- 新建、上传、编辑和预览平台文章。
- 设置文章标题、简介、分类、作者署名、封面（可选）、售价、免费内容截止位置和发布时间。
- 发布、下架和重新发布文章。
- 查看文章基础漏斗数据和订单记录。
- 查看关键管理操作的审计日志。

第一版仅设一个管理员角色，但权限模型不得写死，应预留后续增加编辑、财务和超级管理员的能力。

## 4. 内容工作流

### 4.1 注册用户投稿流程

投稿字段：

- 笔名
- 标题
- 一句话简介
- 完整正文
- 类型
- 联系邮箱或手机号
- 联系方式
- 原创声明确认
- 阅读授权确认

提交后的系统行为：

1. 校验登录状态、必填项、正文长度和内容格式。
2. 执行验证码、频率限制、恶意内容清洗与重复提交检查。
3. 保存原始稿件，不允许后续编辑覆盖原稿。
4. 生成投稿编号，并关联到投稿用户账户。
5. 通知管理员有新投稿。
6. 明确告知投稿者：“稿件已提交。待审核通过后，编辑会通过你填写的联系方式联系你。”

首版不采集收款信息。稿件通过审核后，由编辑联系作者，再通过独立的安全流程确认稿费、授权和收款安排。

投稿状态：

`submitted`（待审）→ `reviewing`（审核中）→ `revision_requested`（待修改）/ `rejected`（未采用）/ `accepted`（已采用）→ `published`（已发布）

状态变更必须记录操作者、时间和备注。

### 4.2 管理员文章流程

管理员有两种来源：

- 从已采用投稿创建文章。
- 直接新建并上传平台文章。

文章状态：

`draft`（草稿）→ `scheduled`（待发布，可选）→ `published`（已发布）→ `unpublished`（已下架）

发布前必须满足：

- 标题、简介、完整正文和作者署名存在。
- 免费内容截止位置有效。
- 售价有效。
- 授权状态已确认。
- 编辑可以预览游客看到的免费部分和付费后全文。

## 5. 前台模块

### 5.1 首页 / 故事列表

- 只展示 `published` 状态的真实文章。
- 默认按管理员设置的精选顺序和发布时间展示。
- 支持标题搜索和单一类型筛选。
- 无文章时显示空状态，不自动生成示例内容。
- 故事卡片展示标题、简介、类型、预计阅读时间和解锁价格。

### 5.2 阅读页

- 服务端只向未购买用户返回免费部分，不能把完整正文藏在前端代码中。
- 显示阅读进度和剩余字数。
- 到付费墙后展示真实价格与解锁按钮。
- 已购买用户直接获得全文。
- 下架文章对未购买用户不可见。原购买者仍可阅读；若因侵权、违法内容或其他合规原因执行全站撤下，则所有用户均不可继续读取正文，并保留处置记录。

### 5.3 登录与账户

- 第一版建议采用邮箱验证码登录，减少密码管理成本。
- 支持退出登录。
- 保留管理员专用登录入口，但后台权限必须由服务端角色校验，不能只隐藏链接。

### 5.4 已购故事

- 展示当前用户已成功付款的文章。
- 支付成功后可立即阅读。
- 空列表显示明确空状态。

### 5.5 投稿页

- 游客可查看投稿说明；提交操作要求注册并登录。
- 首版只支持粘贴纯文本正文，不支持文档上传。
- 展示字数统计、格式要求、原创与授权说明。
- 投稿成功后返回投稿编号，不公开显示稿件，并提示审核通过后由编辑主动联系。

## 6. 管理端模块

### 6.1 管理员登录

- 独立路由，例如 `/admin/login`。
- 服务端会话与角色校验。
- 登录频率限制和失败审计。
- 第一版不提供公开管理员注册；管理员账号通过安全的初始化流程创建。

### 6.2 管理概览

- 待审核投稿数量。
- 已发布、草稿和下架文章数量。
- 最近投稿与最近发布。
- 第一版只展示有真实数据的指标，无数据时显示零值和空状态。

### 6.3 投稿审核

- 按状态、类型和提交时间筛选。
- 查看原始稿件和投稿人信息。
- 填写内部备注与对外反馈。
- 执行开始审核、要求修改、拒绝、采用操作。
- 采用稿件时创建文章草稿，但不能自动发布。

### 6.4 文章管理

- 新建文章、上传正文、编辑元数据。
- 富文本能力以“章节/段落编辑 + 安全格式化”为主，不引入复杂排版系统。
- 设置付费墙位置与售价。
- 前台预览。
- 发布和下架；第一版不做定时发布。
- 文章正文保存版本，发布后的修改可追溯。

### 6.5 订单与购买记录

- 查看订单号、用户、文章、金额、状态、支付渠道和时间。
- 支付状态只能由服务端支付回调改变。
- 管理员不能通过普通编辑界面伪造“已付款”。
- 退款属于后续范围，第一版先保留状态与接口边界。

### 6.6 基础数据

- 故事曝光次数。
- 点击进入阅读页次数。
- 到达付费墙次数。
- 创建订单次数。
- 支付成功次数。
- 完读次数（需要明确判定规则）。

派生指标：

- 点击率 = 阅读页访问 / 故事曝光。
- 付费墙到达率 = 到达付费墙 / 阅读页访问。
- 解锁率 = 支付成功 / 到达付费墙。
- 完读率 = 完读 / 支付成功。

所有指标必须标注口径，不能将页面刷新当作独立用户。

## 7. 数据模型边界

建议首版核心实体：

- `users`：用户身份与状态。
- `roles`、`user_roles`：可扩展角色权限。
- `submissions`：投稿当前状态与联系信息。
- `submission_versions`：原稿与修改稿版本。
- `submission_reviews`：审核动作、备注与审计信息。
- `authors`：公开作者信息，与登录用户解耦。
- `stories`：文章元数据、状态、价格与发布信息。
- `story_versions`：正文版本和付费墙位置。
- `orders`：支付订单。
- `purchases`：支付成功后生成的阅读权益。
- `entitlements`：统一阅读权益；来源可以是管理员人工授予、未来支付订单、赠阅或客服补偿。
- `reading_events`：经过去重的漏斗事件。
- `audit_logs`：关键管理操作日志。

正文与公开元数据分离，订单与阅读权益分离，投稿人与公开作者分离。这些边界可以避免未来加入签约作者、退款、赠阅或多版本内容时重构核心表。

### 7.1 冷启动阅读权益

管理员可以为注册用户授予以下权益：

- `story_full`：解锁指定作品 ID 的全文。
- `category_full`：解锁指定类别下全部已发布作品的全文。
- `platform_full`：解锁全站全部已发布作品的全文。

每条权益都必须包含生效时间，可选到期时间、授予管理员和备注。权限判断同时检查授权范围、作品/类别、当前时间、撤销状态和作品的全站撤下状态。管理员可以提前撤销权益，系统保留原始记录和撤销时间，不物理删除审计数据。

未来真实支付成功后，同样生成 `story_full`、`category_full` 或 `platform_full` 权益，不另外维护一套“付费用户”布尔字段。

## 8. 技术架构建议（Vercel）

### 8.1 推荐结构

- Web：Next.js（App Router）+ TypeScript。
- 部署：Vercel。
- 数据库：PostgreSQL，使用可迁移的数据访问层。
- 身份：独立认证模块，不把页面组件直接绑定某家认证供应商。
- 文件：对象存储；正文的权威版本仍保存在数据库版本表中。
- 支付：支付适配器接口 + 服务端订单 + 签名回调。
- 邮件/短信：通知适配器接口。

### 8.2 可复用架构原则

代码按业务能力分区，而不是按页面把所有逻辑堆在一起：

```text
src/
  app/                 # 路由与页面组合
  modules/
    auth/              # 登录、会话、角色
    submissions/       # 投稿与审核
    stories/           # 文章、版本、发布
    commerce/          # 订单、支付、购买权益
    analytics/         # 漏斗事件与指标
  components/          # 可复用界面组件
  infrastructure/      # 数据库、存储、邮件、支付实现
  shared/              # 通用类型、校验、错误和工具
```

每个模块内部区分：

- 领域规则：与框架无关。
- 应用服务：组织用例和事务。
- 数据接口：定义能力，不暴露具体供应商。
- 界面/API：负责输入输出，不直接承载业务规则。

这使未来更换数据库、认证或支付供应商时，核心业务不需要整体重写。

## 9. 安全与合规底线

- 后台每个请求都做服务端权限校验。
- 付费正文不能在未授权页面源码、接口响应或静态资源中泄露。
- 投稿正文按不可信输入处理，防止脚本注入。
- 联系方式按敏感数据处理，限制读取权限并记录访问。首版不采集收款信息。
- 支付回调校验签名、金额、订单号和幂等性。
- 投稿接口配置验证码、限流、正文大小限制和恶意文件检查。
- 管理操作与发布动作保留审计记录。
- 数据备份、删除、作者撤稿和用户隐私请求需要在上线政策中明确。

## 10. 建议开发顺序

用户确认本文档后，按以下独立模块逐个实施和验收：

### 模块 0：工程与数据基础

- Next.js/TypeScript 工程、环境配置、数据库迁移、错误处理、日志、基础布局。
- 空数据库启动，禁止 seed mock 数据。

验收：本地与 Vercel 环境均可启动；数据库迁移可重复执行；所有列表为空时页面正常。

### 模块 1：身份与管理员入口

- 用户登录、管理员入口、服务端会话和角色权限。

验收：普通用户无法访问任何管理接口；不存在前端隐藏即授权的问题。

### 模块 2：注册用户投稿

- 投稿表单、纯文本正文、联系方式、校验、限流接口、投稿编号和原稿版本保存。

验收：未登录用户不能提交；注册用户可提交真实稿件；恶意 HTML 不执行；重复或超限请求被拒绝；不采集收款信息。

### 模块 3：投稿审核

- 管理员投稿列表、详情、状态流转、备注、采用生成草稿。

验收：非法状态跳转失败；所有审核动作可追溯。

### 模块 4：文章管理与发布

- 管理员直接上传、编辑、版本、付费墙、预览、发布和下架。

验收：未发布文章不会出现在前台；发布版本与编辑草稿互不污染。

### 模块 5：前台阅读

- 空首页、真实故事 Feed、搜索/分类、阅读页和服务端正文权限裁剪。

验收：未购买请求无法通过查看源码或接口拿到付费正文。

### 模块 6：订单与真实支付

- 订单创建、支付适配器、回调、幂等处理和购买权益。

验收：只有可信支付成功回调才能生成购买权益；重复回调不会重复记账。

### 模块 7：已购书架与基础数据

- 已购故事、阅读恢复、漏斗事件和管理员基础指标。

验收：购买权益跨设备有效；指标口径有说明且事件去重。

### 模块 8：上线准备

- 安全检查、备份策略、隐私与投稿协议、错误监控、域名和生产环境配置。

验收：关键失败路径可观测；没有测试账号、测试订单或 mock 内容进入生产环境。

## 11. 暂不开发

- 作者后台与作者自助发布。
- 自动稿费/分成结算。
- 评论、点赞、关注和站内私信。
- 推荐算法和个性化 Feed。
- 排行榜、等级、积分与金币。
- AI 写作或 AI 审稿结论。
- IP、短剧、漫画和影视版权交易。
- 多语言与原生移动 App。

## 12. 已确认的产品决策

1. 投稿必须注册并登录；投稿表单只收集联系方式，不收集收款信息。
2. 投稿成功提示审核通过后由编辑主动联系。
3. 首版正文只支持粘贴文本，不支持 `.docx` 上传。
4. 下架文章仍向原购买者开放；因侵权或合规全站撤下时例外。
5. 第一版不做定时发布。
6. 阅读端加入用户水印；水印是追责和威慑手段，不承诺绝对防盗。
7. 支付能力需要同时考虑不同地区用户，但当前只有 AlipayHK、支付宝和微信个人收款码，尚不具备生产级自动交易条件。

## 13. 尚待确认或外部解决的问题

1. **身份验证方式**：注册采用邮箱验证码、手机号验证码，还是两者均支持？
2. **支付主体和商户能力**：正式上线交易前，需要确定经营主体、目标结算地区和可提供服务端回调的商户支付产品。
3. **中国大陆合规路径**：付费发布原创文学可能涉及 ICP 经营许可、网络出版服务许可及内容审核责任，应在公开收费前由熟悉互联网出版的专业人士核实主体和许可证要求。
4. **水印字段**：建议显示脱敏用户标识、订单尾号和动态时间，不直接暴露完整手机号或邮箱。
